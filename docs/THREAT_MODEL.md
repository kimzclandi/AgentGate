# 威胁模型

资产：租户资源、用户身份、受限委托、审批完整性、业务副作用、模型 Key、审计证据和运行可用性。

可信边界：浏览器/模型/文档内容不可信；Go 认证授权代码、部署配置、SQLite 和宿主操作者可信。客户端与 HTTP、模型提供商与规划器、控制面与 DB 是主要边界。没有不可信代码插件。

| 攻击面 | 控制 | 剩余风险 |
|---|---|---|
| 伪造令牌 | 成熟库验签/声明校验、可信 subject 映射 | 开发签发 CLI 由本机用户控制，不适合公网 |
| 跨租户 IDOR | 每次 tenant+owner+kind 查询 | DB/服务代码被控制不在应用隔离范围 |
| 越权委托 | 用户/Agent/运行 scopes 交集 | 没有多级 delegation 协议实现 |
| 审批替换/重放 | 规范化参数绑定、认证确认、唯一键与事务 | 双人审批/审批人组织分离未实现 |
| TOCTOU | 本地资源与撤销统一事务串行化 | 无法延伸到远端 API 的事务 |
| 提示注入 | 文档/返回仅作数据；模型无审批权；统一 PEP | 不声称防住所有自然语言欺骗或任务误解 |
| SSRF | 无 URL 工具；模型固定主机、IP 校验、禁代理/跳转 | 宿主信任与未来新增代码仍需审计 |
| 路径/符号链接 | 不接受文件路径、不暴露文件工具；随机工作目录 | 非容器沙箱，不防恶意宿主 |
| DoS | 并发、步骤、超时、输出限制 | 单实例全局限额可被单租户占满；无长期存储配额 |
| 日志泄密 | 不记录 token/key/完整资源正文；拒绝事件不暴露资源存在性 | 审批表保留工单内容，对话表保存用户问题及完整工具返回；应制定保留期并保护数据库备份 |
| 审计删除 | 业务成功必须与审计同事务提交 | 应用追加不是 WORM，不防数据库管理员篡改 |

## 已知限制 / 优先级

P1 上线前：真实 OIDC 登录与 token profile、服务身份、TLS、租户配额、独立审计出口、部署密钥管理、备份恢复、远端模型/IdP 回归。当前不接受公网生产上线。

P2 后续扩展：更细角色与团队资源 ACL、审批管理员、完整 metrics 时序导出、远端连接器 unknown 对账、策略变更 API、持久存储保留策略。

数据库不可用时受保护操作失败关闭。此时无法承诺审计落库；HTTP 返回通用依赖错误，避免假造审计成功。认证查库失败当前统一 401，不泄露身份是否存在；就绪检查 503 帮助区分运维故障。
